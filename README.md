# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 调速器校验链路

调速器「提交校验」不再只改状态：在校验面板填入油压值、导叶开度、接力器行程、开度限位与
校验日期后，`submitCalibration`（`frontend/src/api/local-service.ts`）把这五项随状态一次性
写进台账，列表页、详情面板与导出的装置清单读的都是这同一份数据；页脚的待校验装置台数、
水情调度页的待调度记录（联动口径：水情待调度 + 调速器待校验）随之更新。

写入防线按序执行，任何一道不过都整笔退回、一个字段都不写：

1. **并发**：面板打开时记录版本基线 `revision`，提交时对不上说明另一入口已改过，后到的整笔拒绝；
2. **状态**：已停用装置不再接受校验；
3. **字段**：数值要在量程内（油压 0~25 MPa、开度/限位 0~100%、行程 0~2000 mm），
   校验日期要合法且不晚于今天；
4. **幂等**：五项与库中完全相同的重复报送只算一次，后到的退回；数据不同的再次提交视为
   新一轮校验，覆盖生效（同一台连续提交只落最后一次）。

通过后在内存里拼好整行再一次持久化，中间不落地写了一半的记录。旧的
`runAction('governor', id, '提交校验')` 裸改状态入口已封堵，防止再出现只写状态不写字段的记录。

## 存量数据兼容（schema v2）

数据层带版本号（`hydropower-plant-om:schema`），低于 v2 的存量数据在首次读取时自动迁移，
迁移幂等、只跑一次：

- 所有模块的记录补 `revision`（并发基线，缺省从 1 开始）；
- 调速器历史记录按装置分组、组内按校验日期升序回填缺项：先沿用本组上一次有效值，
  组首就缺的用本组下一次有效值，整组都缺才落兜底值（油压 6.3 MPa、开度 0%、行程 0 mm、
  限位 100%）；被补录的记录打 `补录来源 = 迁移补录` 标记，详情面板可见，人工提交校验后标记清除；
- **既有的状态等级（待校验/正常/异常/已停用）一律不改写**，迁移只补缺字段，不碰业务结论。

跨标签页通过 `storage` 事件失效本地缓存，两个入口读到的对得上；localStorage 损坏时回退到
迁移后的种子数据。

## 自检

数据层链路（迁移回填、原子提交、幂等、并发、持久化）有两份 node 自检脚本，不依赖浏览器：

```bash
cd frontend
npm run check
```

脚本位于 `frontend/scripts/governor-calibration.check.ts` 与
`frontend/scripts/local-store-persistence.check.ts`，由 `scripts/run-checks.sh` 编译后运行，
覆盖：缺项回填、五字段一次性落库、重复报送退回、连续提交只落最后一次、并发只生效第一笔、
非法输入整笔退回、刷新后记录保持、跨标签页一致、localStorage 损坏回退。
