# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 调速器校验链路（governor）

「提交校验」不是单纯的状态翻转，而是一笔跨模块事务，规则集中在
`frontend/src/api/governor-service.ts`：

- **整笔齐写**：油压值、导叶开度、接力器行程、开度限位、校验日期与「正常」状态在同一次
  提交里写入调速器台账。任一项缺填、非数值或越界（油压 0~10MPa、开度/限位 0~100%、
  行程 0~500mm、日期不晚于今天），整笔退回，不落只写一半的记录。
- **一个数据源**：列表页、详情抽屉、CSV 导出都从同一份已提交台账现读；详情面板每次打开
  重新取数，提交后返回列表、刷新页面，两个入口读到的一致。
- **待校验台数**：页脚与指标卡只把「待校验」状态算作待办，提交成功后实时减一；
  「异常」由「标记异常」单独体现，不再混入待校验。
- **连提只留最后一次**：同一台装置可反复提交，台账始终保留最新一次读数；每次提交带
  行版本号 `_rev`，基于旧版本（别人/另一面板已提交过）的提交整笔拒绝写入。
- **重复报送退回**：同一台装置提交与在库读数完全等价（数值归一化后比较）的数据时，
  后到的一份直接退回，不产生新版本。
- **并发第一笔生效**：同一台装置并发提交时只允许第一笔落库，后到的整笔拒绝；落库
  （`localStorage.setItem`）抛错时内存缓存不替换，调速器与水情改动整套退回。
- **跨模块联动**：与校验日期同一天、仍处于待调度口径（待观测/已观测）的水情记录，随
  校验结论一起推进到「已调度」并写入联动说明；水情页页脚的待调度条数随之变化。
- 另存的装置清单（导出 CSV）与台账同源同字段，不包含联动说明等内部列。

### 存量数据兼容（schema v1 → v2）

首次加载旧库时由 `frontend/src/data/migration.ts` 自动迁移一次，迁移结果与一个
`hydropower-plant-om:meta`（schema 版本 + 补录台账）一起原子写入：

- **历史回填**：已校验（正常/异常）的历史记录按校验日期排序回填缺项，缺项只补读数、
  **既有等级原样保留不改写**。补录口径固定：油压值按额定压力油源 2.50MPa、导叶开度按
  额定 80.0%、接力器行程按开度×2.0 传动比（全行程 200mm）、开度限位按机械全开 100%；
  缺校验日期的按存量记录时间顺序，从最早已知日期往前每 30 天排一条。
- **缺项单独补录**：每一条被补录的字段都登记进独立的「历史缺项补录台账」
  （调速器页按钮查看），记录装置、校验日期、补录字段与口径；装置台账里对应记录带
  「补」标记，不虚增行。
- **不虚构数据**：待校验/已停用记录上的旧占位读数（如「调速器样例1」）直接清空，等真正
  提交校验时填实测值；水情旧占位水位/流量同样清空，只重算待办标记。
- 迁移只执行一次；`resetModule('governor')` 后种子数据走同一套补录口径，同一装置同一
  字段不会在补录台账里重复记账。

### 链路自检

```bash
cd frontend
npm run verify
```

该脚本用内存版 localStorage 跑 11 项集成校验：整笔齐写、缺项退回、连提覆盖、重复报送
退回、并发第一笔生效、乐观锁拒绝、写失败回滚、v1 迁移回填、刷新后多入口一致、
导出与台账一致、待校验台数联动。
